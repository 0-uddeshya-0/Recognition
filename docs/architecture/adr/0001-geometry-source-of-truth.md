# ADR-0001 — IFC4 is the exchange truth; the Python DSL is the geometry truth

**Status** Accepted · 2026-08-22
**Context layers** L3, L4

## Context

The system must produce a 3D model and 2D drawings that (a) a compliance engine can reason
about semantically, (b) real CAD tools can open, and (c) an agent can safely modify.
Three candidate kernels were on the table: IfcOpenShell (IFC4), CadQuery/build123d (OCCT),
and OpenSCAD (mesh CSG).

## Decision

- **IFC4 via IfcOpenShell is the exchange source of truth (SoT-4).**
- **`design/<project>.py`, a constrained Python DSL, is the geometry source of truth (SoT-3).**
  The IFC is generated from it and never edited.
- CadQuery/build123d is deferred to phase 3 for *component* detail (stairs, railings,
  joinery) exported to STEP and imported into the IFC.
- OpenSCAD is not adopted.

## Rationale

Compliance needs semantics, not triangles. `ROOM-DAYLIGHT` must ask "what is the net floor
area of this bedroom and the glazed area of its windows". `IfcSpace` carries category, name
and area; `IfcWindow` relates to its opening and host wall. A mesh union cannot answer
either question — this alone eliminates OpenSCAD as the building kernel, and it is also a
separate non-Python language adding a toolchain for capability IFC already covers.

CadQuery and build123d are excellent B-rep kernels, but they model *parts*. They have no
storey structure, no space concept and no property sets. Right tool for a fabricable stair;
wrong tool for a building.

The DSL sits above IFC because of **reviewability**. An IFC diff is unreadable and an agent
editing IFC directly can produce a file that parses but is architecturally nonsense. The DSL
is ~40 lines for a six-room house, every number is a dimension in metres, and a diff shows
exactly what moved. A human can review an agent's proposed change in thirty seconds. That
reviewability is the safety mechanism, not a convenience.

## Consequences

- Anything the DSL cannot express does not exist in the system. v1 accepts that: rectangular
  single-storey envelopes only. Roofs, slabs, stairs and materials are out of scope.
- The IFC can be deleted at any time and regenerated byte-identically — which is what makes
  the regression half of the L5 gate possible.
- LGPL-3.0 (ifcopenshell) is fine for an imported, unmodified Python library. Revisit only if
  a modified static binary is ever shipped.
